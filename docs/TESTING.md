# Перевірки та діагностика

Підсумок виконаних перевірок публічної копії: [VALIDATION.md](VALIDATION.md).

## Три рівні

1. **Логіка на комп’ютері.** `python tools/run_host_tests.py --core-only` запускає 10 наборів без USB. Повний `python tools/run_host_tests.py` запускає 14 наборів після отримання PlatformIO-бібліотек. Це тести production helpers, RTC.cpp, OneButton і модуля черги зі stub-залежностями; вони не емулюють весь радіочип.
2. **Збірка.** `python tools/build_firmware.py` компілює `t-echo-plus`, компонування, бібліотеки та пакети DFU. Перевіряйте і чистий публічний режим, і власні локальні ID/opt-in перед встановленням.
3. **Фізична пара.** Після прошивання перевіряйте конфігурацію, свіжість датчиків, екран, час, доставку в обидва боки й відновлення після розриву. Збірка та host-тести цього не доводять.

| delivery_payload | Розмір protobuf разом із PKI й межею радіопакета, UTF-8 |
| delivery_module | Реальний модуль: FIFO, повтори за подіями, receipt, dedupe, перезапуск, помилки запису, перевірена заміна ключа |

## Перевірка після встановлення

1. Прочитати `--info`/експорт конфігурації обох рацій. Порівняти локально з резервними копіями: власні PKI-ключі, канал, назви, регіон, модем, timezone, 24h. Експорт містить секрети — не вкладати його у публічний issue.
2. Упевнитись, що контакт містить актуальний відкритий ключ фізично перевіреної другої рації. За потреби виконати `tools/pair_usb.py trust` за [PAIRING.md](PAIRING.md).
3. Надіслати короткий особистий текст із `Ї Є Ґ` A → B та B → A. Звірити текст на одержувачі, підтвердження від потрібного вузла та відсутність дублювання.
4. Вимкнути одну рацію, надіслати нове повідомлення, повернути її в ефір. Реальний RX від пари має дати черзі можливість повтору; сам напис Online у телефоні цього не доводить. Повторити після перезапуску відправника. Окремо перевірити межу заповнення черги.
5. Переконатись, що годинник рухається після понад 10 хвилин без USB (`screenOnSecs: 0`) і що прочитання/закриття повідомлення змінює локальний лічильник. Телефон і рація не синхронізують позначку прочитання.
6. У сирих логах порівняти кілька нових конверсій BME280. Зміна цифр не обов’язкова при стабільному середовищі, але надходження нових записів і час вибірки мають змінюватись. За помилки старе число не повинне виглядати актуальним.
7. GPS перевіряти надворі після фіксу. Старі координати, висота у приміщенні й список Online не є доказом поточного положення або робочого маршруту.

## Зібрати калібрувальну точку

Поставте рацію й контрольний прилад поряд. Прочитайте контрольні значення безпосередньо перед командою:

```bash
python tools/capture_calibration.py --port /dev/ttyACM0 --expected-node '!11223344' --reference-temperature 25.2 --reference-humidity 64
```

Скрипт не записує конфігурацію: слухає наступний повний діагностичний запис TH4/TH5/TH6 після ідентифікації. JSON у `.private/calibration/` містить контроль, сирі T/RH/P, MCU, застосовану поправку, режим USB та затримку; у H2 також стан GPIO підсвітки. Повні логи, координати й повідомлення не зберігаються. Час запису локальний приватний; для публікації переносіть лише дозволені числові поля в окремий CSV.

Якщо логів немає, результат позначається помилкою; скрипт не підставляє стару телеметрію. Підключення USB змінює тепловий режим. Таку точку не можна назвати автономною точкою на батареї. Загальний helper підготовлений і перевірений без USB; фізичний збір у дослідженні виконувався його попередником.

## Типові симптоми

| Симптом | Що перевірити |
|---|---|
| `Connection timed out` | Доступ USB для Linux, правильний режим/порт, один власник порту, завантаження рації |
| Від’єднання serial після DFU | Новий USB-пристрій завантажувача потребує доступу Linux |
| Online, але DM не доходить | Вік останнього RX; актуальність контакту/PKI; реальна квитанція; однакові modem/channel/region |
| Trace route порожній | Відповідь не отримана; це не доводить відсутності чи наявності ретрансляторів |
| Нерухомий годинник/температура | Час на e-ink, `screenOnSecs`, свіжі сирі логи, помилки сенсора |
| BME тепліший за кімнату | Сирі дані, режим USB, стабілізація поряд із контрольним приладом; [CALIBRATION.md](CALIBRATION.md) |
| Велика помилка висоти GPS | Фікс і умови приймання; GPS-висота та барометричний тиск є різними величинами |

## Зафіксований результат TH4-R1

Персоналізований TH4-R1 установлено на обидві дослідні рації. Після виправлення застарілого відкритого ключа контакту перевірено збереження конфігурацій, доставку тексту з кирилицею й захищену квитанцію в обидва боки та свіжі сенсорні записи. Початкова перевірка TH4 мала збій PKI; його не приховано під статусом успішної збірки.

Публічна копія має локальні ID й експериментальну корекцію вимкненими за замовчуванням. Після додавання H1 загальний `flash_radio.py` перевірено фізичним прошиванням однієї рації; окремі загальні helpers контактів/калібрування лишаються перевіреними без USB. Докладний стан — [VALIDATION.md](VALIDATION.md). Вуличний діапазон зв’язку, багатоденна автономність, точність на холоді й повний цикл теплового гістерезису залишаються фізичними випробуваннями.
