# Публічні та локальні дані

## Що є в Git

- Вихідний код із базовою upstream-історією та ліцензією.
- Вигадані ID `!11223344` / `!55667788`, назви Radio A / Radio B.
- Шаблони конфігурацій без ключа каналу й без особистих ключів.
- Знеособлені сенсорні числа, формули, результати й обмеження дослідження.
- Тестові байти ключів у host-тестах — синтетичні fixtures, не ключі дослідних рацій.

## Що залишається локально

| Шлях | Вміст |
|---|---|
| `.private/` | Ідентифікатори, приватний URL каналу, YAML, контакти, резервні копії, виміри з часом |
| `src/mesh/PairSettings.local.h` | Справжні ID та opt-in власного профілю |
| `.artifacts/`, `.pio/` | Збірки й пакети; бінарник може містити локальні ID |
| `.local/`, `.venv*/`, `.build-host-tests/` | Локальні інструменти й результати |
| `*.local.yaml`, `*.local.json`, `*.log` | Додаткові приватні матеріали |

Ці шляхи ігноруються Git. Ігнорування не шифрує диск і не видаляє файл, уже доданий у Git. Скрипти створення профілів/резервних копій використовують приватні права доступу; резервні копії слід зберігати захищено.

## Перед публікацією власних змін

```bash
git status --short
git diff --cached --stat
git diff --cached
git check-ignore .private/example.yaml src/mesh/PairSettings.local.h .artifacts/example.zip
```

Перевірте не лише дерево, а й нові коміти: реальні ID (hex і decimal), USB-серійні номери, довгі/короткі назви, канал URL/PSK, PKI private/public keys, координати, повідомлення, імена користувача у шляхах, скриншоти й діагностичні архіви. Контактний QR/URL також містить ідентичність і відкритий ключ.

Для баг-репорту краще додати мінімальний знеособлений лог конкретного збою. Повний `--info` або `--export-config` може містити ідентифікатори, координати чи секрети. Автоматичний сканер корисний, але не замінює перегляд.

Публічні параметри калібрування не містять персональних ID. Водночас вони отримані лише на двох дослідних екземплярах; не використовуйте їх як загальну заводську поправку.
