# Налаштування Radio A та Radio B

## Підготовка

Приклади розраховані на T-Echo Plus із радіотрактом 868 MHz і регіоном `EU_868`. Інший регіон змінюють однаково на обох пристроях з урахуванням апаратної частоти й умов використання.

Активуйте `.venv` за [BUILD-FLASH.md](BUILD-FLASH.md). Приєднайте антени, підключіть рації USB-кабелями з передаванням даних. У ChromeOS дозвольте кожному USB-пристрою доступ до Linux.

```bash
python -m serial.tools.list_ports -v
python tools/pair_usb.py identify --port-a /dev/ttyACM0 --port-b /dev/ttyACM1
python tools/pair_usb.py backup --port-a /dev/ttyACM0 --port-b /dev/ttyACM1
```

Порти можуть змінитися після перезапуску. `identify` читає фактичні ID. Опис TTGO_eink/TinyUSB підтверджує USB-пристрій, але не працездатність Meshtastic API. Один порт одночасно використовує один клієнт.

## Генерація приватних профілів

Цей генератор створює **нову** пару з новим ключем каналу. Для вже чинної пари спочатку збережіть резервні копії; застосування нового профілю замінить її канал. Підставте прочитані ID; нижче — вигадані приклади.

```bash
python tools/make_pair_profiles.py --node-a '!11223344' --node-b '!55667788'
```

Скрипт не підключається до рацій. Він створює:

- `.private/radio-a.yaml`, `radio-b.yaml`: спільний випадковий 256-бітний ключ каналу, однакові радіопараметри, різні назви.
- `.private/pair.json`: локальні ID та секретний URL каналу.
- `src/mesh/PairSettings.local.h`: ID для коду пари; температурна корекція початково вимкнена.

Якщо будь-який із цих чотирьох файлів уже існує, генератор зупиняється до створення нового ключа й нічого не перезаписує. Для чинної пари редагуйте її збережені локальні файли. Генерація профілю й імпорт контакту не створюють нових PKI-ключів та не копіюють приватний ключ однієї рації на другу. Водночас резервний YAML-експорт може містити власний приватний ключ і ключ каналу — зберігайте його локально.

Публічні [radio-a.yaml](../config-examples/radio-a.yaml) / [radio-b.yaml](../config-examples/radio-b.yaml) не мають ключа і самі по собі не створюють приватний спільний канал.

## Застосування YAML

```bash
meshtastic --port /dev/ttyACM0 --configure .private/radio-a.yaml
meshtastic --port /dev/ttyACM1 --configure .private/radio-b.yaml
```

Дочекайтеся запуску між операціями; за потреби повторно надайте USB-доступ Linux. CLI може вивести секретний URL каналу в термінал — такий вивід не публікують.

| Параметр | Значення |
|---|---|
| Роль | CLIENT |
| LoRa | EU_868, LONG_FAST, slot 1, hop limit 3 |
| GPS | Зчитування 8 с, тестовий broadcast 15 с, smart off |
| Датчики | Вимірювання у прошивці 15 с, environment broadcast 60 с |
| Екран | 24 години, carousel off, screenOnSecs 0 |
| Часова зона | Приклад EET/EEST із сезонним переходом |
| Сповіщення | Вібрація тексту, buzzer disabled |
| MQTT | Вимкнено |
| BLE | Увімкнено, RANDOM_PIN |

15 секунд — тестовий інтервал, а не гарантія отримання координат. Потрібні свіжий GPS-фікс і доступний ефір; обмеження ефірного часу не вимикаються. Для щоденної роботи інтервал можна збільшити. Device telemetry у публічному прикладі — раз на годину; це відрізняється від одного досліду з практично вимкненим device broadcast.

## Прошивка й контакти

Зберіть та встановіть прошивку за [BUILD-FLASH.md](BUILD-FLASH.md). Один пакет із вашим локальним файлом ID підходить обом пристроям.

Після налаштування регіону й запуску:

```bash
python tools/pair_usb.py trust --port-a /dev/ttyACM0 --port-b /dev/ttyACM1
```

Скрипт звіряє обидва ID з `.private/pair.json`, власні відкриті ключі фізично підключених рацій із їх записами у NodeDB та обидва контакти до першого імпорту. Після імпорту й повторного підключення перевіряє точні ключі контактів, verified-позначки та власні ідентичності. Збереження після перезапуску й успішна двостороння доставка перевіряються окремо. Це довіра до локального USB-підключення; нові приватні ключі не створюються.

У модифікованій прошивці явно verified **локальний** імпорт може також переприв’язати відкладені повідомлення до підтвердженого ключа. Текст і ID зберігаються; повтор чекає реальної RX-події. RF NodeInfo, MQTT, неперевірений контакт і віддалений admin цього не роблять. Після перерваного запису може знадобитися повторний імпорт.

Android/iPhone підключаються до своєї рації через Meshtastic-клієнт. Після відновлення ключів оновіть контакт у телефоні теж. Verified-позначка на рації захищає ключ від неперевіреної заміни старим контактом клієнта.

## Перевірка

Нижче — процедура приймання нової публічної збірки, а не твердження, що вона вже пройшла апаратні тести. Фізичні досліди попередніх персоналізованих версій описані окремо в [TESTING.md](TESTING.md).

Надішліть текст із кирилицею A → B, потім B → A. Перевірте текст на одержувачі й квитанцію на відправнику. Online у телефоні не є підтвердженням доставки.

Власний протокол черги потребує цієї модифікації на обох раціях. Звичайні ретранслятори можуть переносити зашифровані пакети; їх доступність перевіряють фактичним маршрутом і доставкою. RX, Relays і ChUtil не показують кількість доступних ретрансляторів.

Для іншої дальності preset змінюють узгоджено на обох. Автоматичного LONG_FAST ↔ LONG_SLOW тут немає; одностороння зміна розділить пару.
